# 问题难度评估

在 **Difficulty** 选择一个地铁、小队或融合场景，也可以用 **Use workspace setup** 把工作区的场景和设置复制过来。输入种子、每个探针的候选预算和规划时刻，运行后可导出 JSON 和逐种子 CSV。在线版在浏览器 Worker 中计算，本机 API 返回同一种报告。

## 结构与编码

地铁使用每站每线一个随机键。三个带标签的线路共有 `3N` 个随机键，其中 `N` 是当前开放站数。评估器用引擎的路径代价统计在轨道总预算、单线停站上限和当前地形下可用的有序线路组合。正反方向分别计入，空线路也计入。列出的剩余改线预算单独约束部署，所以对受改线预算限制的检查点，结构计数是上界。

小队控制器有四个连续参数和两个开关。结构参照将每个连续参数离散为 `k` 档，得到 `4 × k⁴` 个组合，实际优化仍用连续值。融合的原始向量为 `3N+6` 维，结构参照是地铁计数乘以小队离散组合数。切换联动会改变状态轨迹和评价。两侧地图、地形及初始候选结构仍由各自原始引擎确定。

报告还记录可通行地块、剩余改线预算和存活单位。于指定检查点重新评价时，以该种子的初始方案向前模拟到检查点。小队时钟每秒十步，地铁和融合每步相当于一个地铁分钟。整局已结束的种子仅保留结构结果。

## 搜索实测

每个种子和规则设置首先评价初始候选，再用独立的参考样本做校准。参考样本含 `B` 个均匀向量和 `B` 个初始候选附近的向量，`B` 是每个探针的预算。局部样本扰动 1–3 个坐标。报告给出均匀样本的可行比例、解码后的不同候选数和不同分数数，以及可行局部样本中得分不变的比例。

默认目标是 `初始分 + 80% × (参考样本最佳分 − 初始分)`。若样本没有找到改善，该种子标为无目标，并从命中率分母剔除。独立的均匀随机搜索和平台实数 GA 各使用最多 `B` 次候选评价，预算含初始候选。报告显示半预算与全预算命中数、预算用完仍未达标的比例、命中时的平均评价数。未达标比例是给定场景、种子、算法与预算下的实测难度，参考最佳分也是本次实测值。

## 联动对照

融合场景可以以相同地图和种子再执行一次关闭联动的评估。每种设置独立确定自己的经验目标。检查点为 0 时，评估器还把最多 3 个可行线路编码和 3 个控制器编码交叉组合，对两种设置使用同一候选网格。报告分数中无法由两个变量的单独作用解释的比例，以及最大的两行两列交互差。网格没有形成足够的可行变化时标明样本不足。

非零检查点的两种设置各自推进其初始轨迹，结果反映各自到达的状态。规划用平台原有的评价机制，动态场景和中途决策可能使用短期预测。

## HTTP API

向本机的 `POST /api/difficulty` 发送 JSON。可省略的设置采用网页默认值。

```json
{
  "problemId": "fusion",
  "scenarioId": "lumen--contact",
  "seeds": [26, 27, 28],
  "evaluations": 24,
  "checkpoint": 0,
  "gridLevels": 5,
  "targetPercent": 80,
  "config": { "coupling": "both" },
  "compareUncoupled": true
}
```

响应版本为 `hex-difficulty/v1`。响应含规范化设置、各档结构、逐种子参考分和探针曲线。轨道和离散组合计数用十进制字符串存储，确保大整数精度。
