# 问题融合器

## 特性表驱动的规则融合

打开 **Rule fusion**，选择两张场景图、种子和设计目标。**Base problem feature tables** 直接读取适配器的「元素 × 操作」契约。展开单元格可查看执行者、阶段、条件和编译器读取的绑定。**Rule inference** 中的标签可跳回对应单元格。

编译器匹配单一线路写入者、多阵营控制、两种时钟、逐站送达、可分配的生命恢复和原始约束。中立施工、轮流施工和按站点分区施工可分别搭配按缺失 HP 比例分配或等额后再分配剩余补给，得到六个候选。地铁写权限标为可改动时才允许轮流施工。每个合格候选使用所选种子及下一种子，轮换首手阵营运行试验。**Candidate simulations** 列出原始试跑、首段换线、关闭公共补给的成对对照和最终选择。

施工策略对各阵营执行等额轨道配额。轮流施工采用两轮蛇形顺序，每回合提交一条合法的起始连接、端点延伸或跳过。候选延伸依据实际轨道占用格筛选，再经地铁引擎提交。分区策略限制阵营可编辑的站点，允许使用共同枢纽。施工期间两套仿真时钟保持静止。锁定轨道后，地铁按原有规则载客和送达。到站补给存在公共站点库存，同站各阵营的存活伤员按选中方式共享库存。

**Run selected design** 把编译结果送入独立回放。回放记录每个阵营的施工动作、锁轨事件和补给分配。**Run same design with supply off** 固定轨道方案、种子和首手，以观测公共补给对终局 HP 的影响。**Open in Play** 可手动提交当前回合的施工，或让所选算法依次为当前阵营选择合法动作。试跑使用构造式施工与相同的原生交战策略。种子、每回合动作、已选规则及版本随回放保存。实验命令为 `npm run benchmark:topology`。

## 单线轨道约束

新局默认使用简单路径。系统展开每一段停站连接，单线的相邻路段只在公共端点连接，其余六边形格各自最多使用一次。站序之外的暗中折返同样会被拒绝。分段路径采用确定性选路，正反两个方向的轨道几何一致。不同线路的几何分别校验，换乘仍由公共停靠站提供。历史记录缺少拓扑字段时，按历史规则重建，当前回放带有明确拓扑字段。

## 空间融合

在 **Problem analysis** 可分开选择地铁场景和小队场景，直接预览实际生成的站点、轨道、地形和部署。更改 **Scenario settings** 会重建场景、更新搜索空间，并随链接传给算法对比与回放。**Search measurement settings** 单独控制检查点、采样预算和小队参数的离散层数。

## 运行时组合与调参

- **同类组合。** 地铁可保留选定城市的站点、地形和开站时间，采用另一座城市的客流强度。可额外调整客流百分比、轨道预算、每线停站上限、载客量和动态改线预算。小队可保留选定场景的编制与部署，换用另一张图的地形。系统保护部署格可通行，并可按比例缩减其他阵营的编制。
- **跨问题组合。** 共享网格按输入地图、种子和小队的 Q/R 偏移装配。编译器按场景能力、联动方向、补给量和库存限制启用逐站补给、局部调度延误等已定义规则。半径、储量、权重、检查间隔和铁路准备时间均可直接调整。
- **按地图拟合。** **Fit rules to map** 为补给和延误分别尝试 1–4 格的半径。补给匹配开局友方部署覆盖率，延误匹配开局受压轨道段的覆盖率。选择最接近设定目标的半径，平局按与标准半径的距离、半径大小择优。指定非零半径时采用固定值。预览的 **Radius selection evidence** 展示每个候选值的开局覆盖率。真实联动在推进中继续依据当前状态触发。
- **配置一致性。** 自定义数据与归档按同一配置匹配。没有匹配归档时，可从回放页运行所选种子。新增领域规则时需定义可交换的事件或状态和相应效果，再加入规则目录。

## 工作台

打开 **Problems → Problem Fusion**，分别选一张地铁地图和一张小队地图。在 **Episode settings** 选择联动方向、地铁目标权重和两边的原始设置，再点击 **Apply setup**。当前 5 张地铁图和 6 张小队图生成 30 个地图组合。设置、随机种子和实际动作随实验报告和回放一同保存。

## 联动规则

| 设置 | 地铁送达影响小队 | 小队状态影响地铁 |
|---|---|---|
| Two-way coupling | 开启 | 开启 |
| Metro supports squad | 开启 | 关闭 |
| Squad affects metro | 关闭 | 开启 |
| Uncoupled comparison | 关闭 | 关闭 |

- **补给。** 每位送达乘客产生默认 6 HP 的补给。最多储存 60 HP，新的补给从后续周期起可使用。补给先用于己方生命比例最低的存活伤员，受原最大生命约束。恢复实际消耗计入结果。
- **停运。** 如果己方剩余生命比例落后敌方至少 10 个百分点，或战斗已明确判负，地铁在设定的间隔周期停运一轮，默认每 3 轮。此时列车的行驶和上下客暂停，需求、排队、车站开放和本地时钟继续推进。原线路、乘客和剩余改线预算保留。
- **时间。** 一个联合周期包含 1 个地铁分钟。小队按 0.1 秒原生步长推进，从默认 20 分钟的铁路准备期之后开始。将小队设定时长按整数比例映射到剩余周期，若战斗提前结束，其结果固定，地铁运行到自己的时限。

原有线路上限、站点开放、轨道和改线预算继续由地铁引擎校验。小队继续使用原地图地形、移动、命令归属、击杀和胜负规则。两个地图各用自己的坐标，由补给和停运建立联系。关闭联动时，可以在相同地图、种子和手动命令下与原问题核对。

## 方法与目标

融合问题取两个组件公开搜索协议的交集，支持 20 个共享方法。一个候选包含完整地铁方案和六参数小队控制器。向量算法直接使用两个现有编码拼接的向量。每次评价用独立状态运行同一套联动规则，并校验两个子解。两个子解通过校验后一起部署。

静态场景初始规划使用已知的原需求。动态场景和中途重规划使用最多 30 分钟的独立需求预测，编码和预测均只含当前开放站点。动态车站开放、原有 30 分钟周期以及有间隔限制的战斗压力变化可以触发重新规划。

| 可优化项 | 含义 |
|---|---|
| 地铁送达人数 | 最小化预测送达人数的负值 |
| 地铁资源开销 | 静态使用轨道量，动态使用本次改线开销 |
| 己方剩余生命 | 最小化相对初始最大生命的损失比例 |
| 敌方剩余生命 | 最小化相对敌方初始最大生命的剩余比例 |

单目标联合分使用两个组件的原始分数。对分数 \(x\) 用 \(x/(s+|x|)\) 转换，地铁参考尺度 \(s=10×\) 设定时长分钟数，小队参考尺度 \(s=1000+\) 所有阵营初始最大生命之和。两个分量按 **Metro score weight (%)** 加权后乘 100。

NSGA-II、SPEA2、MOEA/D 用四维目标保留非支配候选，部署时按联合分选择。SPEA2 的距离和 MOEA/D 的分解使用固定目标尺度以处理量纲差异。搜索详情和报告中的目标值保留原单位。

## 接口和复现

融合问题 ID 为 `fusion`，地图 ID 由两个原场景 ID 以 `--` 拼接。通过 `GET /api/problems/fusion` 发现有效组合和字段。手动命令使用 `{type:"component", component:"metro"|"skirmish", action: 原动作}`。接口示例见 [HTTP API](api.md)。

使用 **Experiments** 对比方法。在线版 **Recorded runs** 可载入融合器的验证回放。本机可通过 **Import report** 载入同一份 JSON。运行 `npm run verify:fusion` 可重做覆盖全部地图组合的规则对照和共享算法矩阵。

## 共享地图试验

在融合工作区的 **Episode settings** 选择 **Map layout → Shared axial grid**。地铁与小队使用同一轴坐标网格。岩石和水体对两侧均不可通行，保留既有站点和单位初始部署格。上方合成图显示当前轨道、站点、补给库存和存活单位。

**Spatial rules** 设为 **Automatic · capability priority** 时，生成阶段逐条核对局部调度和站点补给所需的数据与接口。条件满足时启用局部列车延缓与逐站补给。站点库存只能恢复范围内的己方存活伤员，送达后生成的库存从后续周期可用。列车延缓作用于受压区域经过的站间段。

选择 **Automatic · six pilot rollouts** 时，需启用双向联动。三种规则组合各用两个固定生成种子，以 10% 列车移动时段延缓率和 5% 己方初始生命恢复量为预计强度。创建时以平均绝对偏差选中组合，随后将具体规则和版本保存到对局配置，回放从冻结组合重建。

独立试验在 `experiments/spatial-rule-selection`。采用该试验的多目标参考时，场景、种子、规划检查点和规则组合均需匹配。
